## Что сделано

Сделано:
- Экран «Матчи тура»: загрузка по `MATCHES_URL`, состояния загрузки / ошибки (с кнопкой «Повторить») / пустого списка.

- Фильтр «Все / Предстоящие / Завершённые», pull-to-refresh и кнопка «Обновить», подпись `UpdatedAgo`.
- Исправлены два бага из части 2 (ниже).

Бонус (выбрала два пункта из списка):
- **Сохранение избранного между запусками** — самая заметная для пользователя вещь: иначе после перезапуска все звёздочки сбрасываются. Использован `@react-native-async-storage/async-storage` 2.2.0 (версия из `bundledNativeModules.json` для SDK 57, работает в Expo Go и в вебе). Нюанс: запись начинается только после чтения сохранённого значения, иначе стартовый пустой список затёр бы избранное. Данные из хранилища валидируются.
- **Тест на логику фильтра** — это чистая функция, на ней проще всего поймать ошибку при смене правил (например, куда отнести `live`). Тесты в `src/utils/matches.test.ts`, запуск `npm test` (встроенный `node:test` + `tsx`, без jest и нативных модулей). Покрыты фильтр, статусы, форматирование даты и сортировка.

Не сделано: поиск по клубу, тёмная тема.

В `src/config.ts` вместо заглушки `OWNER/REPO` подставлен адрес `data/matches.json` из моего форка — с заглушкой запрос возвращал бы 404.

## Решения

**Фильтр.** «Завершённые» — только `finished`. «Предстоящие» — всё, что ещё не закончилось: `scheduled`, `live` и `postponed`. Идущий матч и перенесённый матч ещё не «история», а отдельной вкладки для них нет. Неизвестный статус тоже попадёт в «Предстоящие» и покажется как есть, экран не сломается.

**Неочевидные случаи в данных:**
- `m7`: `startsAt: null` и статус `postponed` → показываю «Дата уточняется» вместо «Invalid Date»; при сортировке такие матчи уходят в конец.
- `m2`: счёт `0:0` → проверяю `score !== null`, а не «истинность», иначе нули пропали бы.
- `score: null` у матчей, которые не сыграны → показываю «– : –».
- `m4`: статус `live` с полем `minute` → «Идёт, 67′», выделено цветом.
- Время приходит в UTC (`Z`) → форматирую через `toLocaleString`, то есть в часовом поясе устройства.
- Длинное название «Пари Нижний Новгород» → карточка переносит текст, вёрстка не ломается.
- Ответ сервера: проверяю `res.ok` и что `matches` — массив. Если «Обновить» нажали несколько раз, учитывается только последний запрос. Если обновление не удалось, старые данные остаются на экране и показывается сообщение.

## Баги из части 2

1. Звёздочки: проверка на то, в избранном матч или нет, осуществлялась не через true/false, а при помощи indexOf, и если матч не в избранном, то возвращался индекс -1, что в булевых означает true. Список избранного изначально пуст, а значит у всех матчей при проверке возвращалось true, поэтому звёздочки и горели у всех. С добавленным матчем то же самое - он есть в избранном и его индекс 0, что в переводе на Boolean означает false. Поэтому его звёздочка как раз и не горела.  

2. «Обновлено N сек назад»: там toggle мутировал массив и отдавал в setState ту же ссылку, React сравнивает по ссылке поэтому не перерисовывал UI. Поменяла на includes и иммутабельное обновление.

## Как я использовал ИИ

Исопльзовался Claude в бесплатной версии. Подготовка репозитория, форк, клонирование, запуск и дальнейшее добавление коммитов в репозиторий делалось мной вручную. Всю логику и файлы патчей подготовил ИИ. Проверяла работоспособность лично, все звёздочки потыкались, вкладки попереключались, URL поломала, проверила что происходит при ошибке.

## Добавленные библиотеки

- `@react-native-async-storage/async-storage` 2.2.0: сохранение избранного. Работает в Expo Go и в вебе; MMKV не подошёл, потому что требует dev build. Версия взята из bundledNativeModules.json для SDK 57.
- `tsx` (dev): запуск тестов на TypeScript на Node 20 (встроенная поддержка .ts есть только с Node 22.6). Альтернатива jest-expo показалась избыточной для теста одной чистой функции.
- `@types/node` (dev): типы для node:test и node:assert, иначе tsc не проходит.
